# 用 Vibe Coding 搭一套能自动出片的视频渲染引擎

## 《Vibe Coding 造一条自动化视频生产线》EP02 · 视频渲染

---

## 一、开场

这一期，用 Vibe Coding 解决自动化视频生产线最核心的一环——**视频自动渲染**。

先抓住一个关键认知：**AI 最强的本事是处理文本和代码。** 所以想让视频渲染自动化，最聪明的做法就是把视频变成**文本 / 代码 / 数据**来驱动。

我们将整件事分三步来完成：

1. **找技术路径**：让 AI 把"用代码/数据渲染成视频"的现成路线全列出来；
2. **技术选型**：和 AI 对话，对着自己的约束选定技术路径；
3. **技术落地**：让 AI 驱动技术路径按配置自动出片。

---

## 二、找技术路径：让 AI 把能落地的路都列出来

问 AI："我想把视频做成代码/配置自动出片，有哪些现成路线？各自用什么描述画面？" 这些路线内核都一样——**用代码/数据描述画面 → 程序编译成帧 → 合成视频**，区别只在用什么语言、什么引擎：

| 路线 | 代表工具 | 用什么描述画面 | 适合干什么 |
| :--- | :--- | :--- | :--- |
| 网页（React + CSS）渲染 | **Remotion** | React 组件 + CSS/SVG | 前端栈、复杂排版、模板复用 |
| 代码声明动画 | Motion Canvas / Revideo | 写函数描述动画时序 | 代码演示、讲解类动画 |
| 数学公式动画 | Manim | Python 描述几何/公式 | 数学、算法可视化 |
| 像素脚本拼接 | MoviePy | Python 操作像素 + FFmpeg | 纯 Python、简单拼接 |
| 画布/游戏引擎 | PixiJS / Cocos | 在 Canvas 上逐帧画 | 复杂粒子、游戏化动画 |
| 命令行合成 | FFmpeg + 脚本 | 命令拼接 | 批量转码、轻量字幕烧录 |

## 三、技术选型：和 AI 对话选定 Remotion

### 1. 让AI进行全方位对比

AI 默认给一份四平八稳、个个说好话的百科对比，帮不了决策。真正能帮你拍板的，是把每条路的**核心优势**和**劣势**都摆到台面上——它最擅长什么、又会在哪些场景吃力。所以让它做一次全方位对比："每个方案的核心优势是什么？劣势和不适用的场景又在哪？"

| 方案 | 核心优势 | 劣势 |
| :--- | :--- | :--- |
| **Remotion** | 前端 React 栈、复杂排版能力强、模板可跨期复用、命令行出片易自动化 | 不擅长纯后台超长批处理；组件顶层直接读浏览器对象会在打包阶段崩；BUSL 授权（规模化要付费） |
| Motion Canvas / Revideo | 代码声明动画、时序精确，适合代码演示 | 组件/排版生态小，复杂网页级排版吃力，模板要自己攒 |
| Manim | 数学/公式/算法可视化专业 | 学习曲线陡、排版弱、渲染慢，普通 UI 与网页排版不合适 |
| MoviePy | 纯 Python、简单拼接、音轨闪避 | 文字排版繁琐、多层画布吃内存、改了要重跑，自适应排版与复杂文字动效弱 |
| PixiJS / Cocos | 游戏级复杂粒子动画 | 文字换行/对齐计算复杂，标准网页 UI 与文字对齐吃力 |
| FFmpeg + 脚本 | 批量转码、字幕烧录、兜底合成 | 命令语法晦涩、难调试，做不了复杂动效与交互排版 |

> 验收标准与证据状态见 `02-plan/README.md` 校验块。

### 2. 对着自己的约束让 AI 对号入座

回到我的需求：**我们希望可以自动化生成视频，所以固定模板、换数据即可生成不同视频内容是我们的核心需求；让 AI 改内容不容易出错；跨期好维护。** 这几条约束下 Remotion 胜出（决策记录见 `_decisions/why-remotion-over-hyperframes.md`，`verified`）：

1. **固定模板、换数据复用**：React 组件 + 数据分离，改一处主题，全系列生效。
2. **让 AI 接手最稳**：每期只让 AI 填数据、套现成组件，不让它自由发挥结构。
3. **一行命令出片**：`npx remotion render` 是纯命令行，方便接自动化、上云（`paper_spec`，命令与 CompositionId 录制前实跑核对）。
4. **网页生态现成**：CSS、动效、图表库随手拿。

Remotion 对比直接使用 HTML 绘制页面：

| 比什么 | ✅ Remotion | ❌ 直接使用 HTML 绘制页面 |
| :--- | :--- | :--- |
| 模板复用 | 改一处全系列生效 | 每期复制改，越改越乱 |
| 让 AI 接手 | 结构稳，只填数据 | 结构容易跑偏 |
| 长期维护 | 十期后还能管 | 十期后难维护 |
| 授权 | BUSL（规模化付费） | 更宽松 |

## 四、技术落地：Remotion 自动化视频渲染（AI 驱动）

### 1. Remotion 大致怎么工作：为什么 AI 能轻松驱动它

一句话：**用 React 写页面及动画，引擎逐帧截图再合成视频。** 关键是这套流程对 AI 特别友好，而且从页面到成片全自动、不需要人工干预：

- **写的就是网页**：页面长什么样、怎么动，都用 React + CSS 描述——这正是 AI 训练语料里最厚的一块，它写起来最熟、最不容易错。
- **改数据就改片**：内容和模板分离，AI 只要改数据就能出不同的片，正中它"最擅长改文本"的强项。
- **类型兜底**：字段格式用 TypeScript 定死，AI 填错、漏填立刻报错，乱发挥的空间被压到最小。
- **出片全自动**：写好页面和数据后，逐帧截图、合成成片全由引擎自动完成，不用人盯着、不用手动剪辑，天然适合接自动化、批量出片。

### 2. 引擎怎么干活：一份配置，按 type 自动分发

渲染引擎是 `OpenMontage/remotion-composer/`（React + Remotion，`verified`）。规则很直白：**你写一份配置，说清"这段是什么画面、上面叠什么"，主程序 `Explainer` 就按配置里的 `type` 字段，自动找到对应组件去渲染**（完整清单见 `SCENE_TYPES.md`）。现成的模板场景（`custom-templates`，均**共用一套深色科技风主题皮肤 + 白字**，改一处全系列生效）：

| 配置 `type` → 组件 | 做什么 |
| :--- | :--- |
| `intro_scene` / `outro_scene` | 开场 / 收尾大字报 |
| `concept_scene` / `bullet_scene` / `flow_scene` | 概念卡列表 / 要点清单 / 流程图 A→B→C |
| `table_scene` / `comparison_scene` | 通用表格 / 左右对比双卡 |
| `chart_scene` / `stat_scene` | 图表（bar/line/pie/kpi）/ 单个核心数字 |
| `callout_scene` / `quote_scene` / `section_scene` | 提示避坑框 / 金句大字 / 章节分隔 |
| `code_scene`（合成终端）/ `screenshot_scene` | 命令+输出逐行打出 / 截图叠光标点击，**不用真录屏** |
| `CaptionOverlay`（叠层） | 字幕高亮（接口已留，**卡点见 EP03**） |

> 这些是引擎现成的通用组件，照着填就能用，且**视觉风格已统一**（同一套科技风框 + 白字，来自 `theme/` 单一真相源）。想要更强的品牌辨识度，还能让 AI 在它们之上扩一套**自有风格组件库**——这是更大的话题，**后续单独开一期讲**；本期先用现成组件把片子跑通。

### 3. 配置即内容：让 AI 填字段，别让它造组件

不让 AI 发明新组件，只让它照现成组件填一份配置。要个对比卡，就说"做个对比卡，左边传统剪辑、右边代码即视频"，AI 产出的就是这份配置：

```jsonc
// ✅ 只写配置：一个 comparison_scene，Explainer 自动渲成对比卡
{
  "type": "comparison_scene",
  "title": "传统剪辑 vs 代码即视频",
  "leftLabel": "传统剪辑",   "leftValue": "拖时间轴，改一处全手工重排",
  "rightLabel": "代码即视频", "rightValue": "改一行配置，重新编译出片"
}
// ❌ 反面：让 AI 为这一期从零手写一个新组件 ComparisonScene.tsx——
//    既重复造轮子，又把"换数据就复用"的好处弄没了。
```

为什么稳：每个 `type` 的字段都用 TypeScript 定死了格式，**AI 填错、漏填，编译时立刻报错**，乱发挥的空间被压到最小。

### 4. 数字人：同样用 Vibe Coding 做选型与落地

视频要不要一个"出镜形象"做陪衬串场？这件事也没拍脑袋，套用和选渲染引擎一样的方法论——**先定位，再让 AI 做全方位对比（列清每种形象的核心优势与劣势），对着约束选定，最后让 AI 落地。**

**定位**：数字人只是**陪衬、串场**，不是主角；干货主体永远是屏幕上的真实操作。

**选型**（让 AI 把可选形象的核心优势与劣势全方位摆出来，`paper_spec`·决策性判断）：

| 形象方案 | 核心优势 | 劣势 |
| :--- | :--- | :--- |
| 真人出镜（自己 / 找人） | 最可信、有温度 | 要露脸出镜、不可编程批量复用、隐私成本 |
| 写实数字人 / 对口型 | 像真主播 | 易掉进恐怖谷、可信度反而崩；口型/表情是重活 |
| 二次元 / 3D 风格化角色（VRM） | 风格统一、可编程、渲一次到处用、不踩恐怖谷 | 要建模与动作绑定，但可交给 AI / 现成方案 |

**结合约束定夺**：我的约束是不想露脸、要可编程批量复用、风格统一、还要避开恐怖谷——于是选 **3D 风格化角色 `VRMAvatar`**（`src/components/VRMAvatar.tsx`，`verified`），并把定位钉死：**陪衬、坚决不做对口型数字人、不做 AI 生成的假界面**，可信度只靠真实录屏。

**AI 落地**：让 AI 把它搭进引擎——

- **渲一次、按场景取景**：整体渲一次，再按场景裁角落/半身/全身（取景预设，`verified`），不用每场景重搭。

## 五、用在哪：Remotion 自动渲染适合 / 搭配 / 不适合的场景

把引擎跑通后，更值钱的判断是**什么场景该用它、什么场景别硬上**。

### 1. 适合纯自动渲染出片（不需要真实录屏）

模板化、可换数据批量复用、画面由文本/数据就能说清的内容：

- 概念讲解 / 认知框架（`concept_scene` / `bullet_scene` / `flow_scene`）；
- 数据图表、对比、核心指标（`chart_scene` / `table_scene` / `comparison_scene` / `stat_scene`）；
- 开场片头、章节分隔、片尾 CTA（`intro_scene` / `section_scene` / `outro_scene`）；
- 命令/报错演示用合成终端兜底（`code_scene`），无需真录屏。

### 2. 可以"搭配着用"（自动渲染画面叠在真实录屏上）

真人口播或真实录屏当主体时，Remotion 不必独占整屏，而是渲成**透明背景的悬浮叠层**贴上去（`paper_spec`：透明通道导出需 ProRes 4444 / 带 alpha 的 webm，命令录制前核对）：

- 真人口播视频上**悬浮**数据卡、角标、章节标题、字幕高亮（`CaptionOverlay`，卡点见 EP03）；
- 实操录屏上叠**箭头/高亮框/局部 Zoom 标注**，把观众视线引到关键处；
- 画中画边框、转场、品牌水印等"包装层"。

> 一句话：**主体是真实画面时，Remotion 退居叠层**；主体是讲解/数据时，Remotion 独占整屏。

### 3. 不适合（别硬上）

- **真实物理世界**：实拍人物表演、实拍产品、Vlog——该拍就拍，Remotion 不替代摄像机；
- **写实对口型数字人**：恐怖谷 + 可信度崩，本项目明确排除（TAD-01）；
- **高自由度影视级特效 / 逐帧手绘角色动画**：交专业工具，硬写既慢又难看；
- **纯后台超长批处理**：Remotion 是浏览器逐帧渲染，重型批处理用 FFmpeg/原生更划算。

## 六、总结

- **三步**：找路径（AI 罗列现成路线）→ 选型（AI 做全方位对比：核心优势 + 劣势，人结合约束综合权衡）→ 落地（AI 驱动 Remotion 自动渲染）。
- **为什么 Remotion**：模板换数据复用、AI 接手最稳、网页生态现成；代价是 React 栈 + BUSL 授权，不构成门槛。
- **引擎核心**：用 React 写页面及动画 → 引擎逐帧截图自动合成、无需人工干预；一份配置 → `Explainer` 按 `type` 分发现成组件；做内容 = 挑组件、填字段。
- **用在哪**：模板化讲解/数据图表纯自动渲染出片；真人/录屏为主时 Remotion 退居透明叠层；实拍、对口型、影视特效别硬上。
- **数字人也走同一套**：定位陪衬，让 AI 全方位对比真人/写实/二次元三种形象的核心优势与劣势、结合约束选定 VRM 3D 角色再落地，坚决不做对口型。
- **没编程基础也能复制**：会讲需求、结合约束综合权衡、把活交给 AI 即可。

下期 **EP03「字幕匹配」**：用 Whisper 拿到字级时间戳，自动驱动 `CaptionOverlay`，让字幕踩着话音跳。
